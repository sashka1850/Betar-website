# Betar website

Интерактивный прототип первого экрана сайта оптового поставщика счётчиков БЕТАР.

Публикация выполняется автоматически через GitHub Pages из каталога `dist`.

Сайт: https://sashka1850.github.io/Betar-website/

Шапка главной и каталога хранится в `templates/`. После правок шаблонов обновите обе страницы командой `python3 scripts/build.py`. GitHub Actions запускает её перед публикацией.

## Локальная проверка отправки прайса

Нужен Python 3.11 или новее. Из корня проекта создайте отдельный каталог состояния и положите в его подпапку `prices` один тестовый файл в нужном формате.

```sh
betar_state=$(mktemp -d)
mkdir -p "$betar_state/prices"
printf 'Демонстрационный прайс\n' > "$betar_state/prices/Прайс.txt"
python3 -B -m server.price_local --state "$betar_state" serve
```

Откройте `http://127.0.0.1:8000/` и отправьте форму на тестовый адрес. Письмо с вложением сохранится в `outbox` в формате EML. Статус и время отправки появятся в `leads.sqlite3`, таблица `price_requests`. Повторный успешный запрос на тот же адрес открывает новый цикл и отсчитывает срок заново. Тексты писем лежат в `server/mail`.

Для импорта входящего письма и запуска проверки дожима используйте тот же каталог состояния в отдельном терминале:

```sh
python3 -B -m server.price_local --state "$betar_state" reply /path/to/reply.eml
python3 -B -m server.price_local --state "$betar_state" follow-up
```

Для ответа в цепочке укажите в тестовом EML адрес клиента в `From` и идентификатор исходящего письма в `In-Reply-To`. Новое письмо с того же адреса без заголовков цепочки тоже может обновить статус текущей заявки. Для исторических писем передайте фактическое время получения через `--received-at` (Unix timestamp). `review` означает, что письмо требует ручной проверки. Импортируйте свежие входящие перед запуском дожима.

Команда дожима перечитывает `server/price_settings.toml` при каждом запуске. Для быстрого теста сдвиньте `sent_at` и `status_at` **в тестовой БД** на восемь дней назад. Для регулярного запуска на хостинге потребуется планировщик и интеграция с почтовым ящиком. Локальные команды складывают письма на диск. Для реальной отправки Python-обработчик поддерживает SMTP с TLS и отдельный адрес для ответов через `PRICE_REPLY_TO`.

## Вариант на Google Apps Script

Версия в `server/apps-script` использует Google Drive для прайса, Google Sheets для заявок и Gmail для отправки и поиска ответов. Она работает отдельно от локального Python-сервера.

1. Создайте Apps Script под обычным аккаунтом Google с Gmail. Используйте ящик, от имени которого нужно отправлять письма и принимать ответы. Подписка Google Workspace для этой схемы не требуется.
2. Скопируйте `server/apps-script/Code.gs` в проект. В настройках включите отображение манифеста и перенесите `appsscript.json`. Создайте закрытую таблицу и папку Google Drive. Загрузите в папку один файл (например, XLSX или PDF).
3. В **Настройки проекта → Свойства скрипта** задайте:

   | Свойство | Значение |
   | --- | --- |
   | `SHEET_ID` | Идентификатор таблицы |
   | `PRICE_FOLDER_ID` | Идентификатор папки с прайсом |
   | `SITE_ORIGIN` | Origin сайта без пути, например `https://sashka1850.github.io` |
   | `TEST_RECIPIENT_EMAIL` | Ваш тестовый адрес. Пока свойство задано, прайс и дожим уходят только на этот адрес |
   | `FOLLOW_UP_ENABLED` | `false` на время проверки, `true` для рассылки |
   | `FOLLOW_UP_DELAY_DAYS` | `7` |
   | `PRICE_SUBJECT`, `PRICE_BODY` | Необязательная замена темы и текста первого письма |
   | `FOLLOW_UP_SUBJECT`, `FOLLOW_UP_BODY` | Необязательная замена темы и текста дожима |

4. Для ежедневной проверки ответов и дожима запустите `installDailyTrigger` в редакторе и подтвердите доступы. Триггер работает от имени установившего его аккаунта и запускается ежедневно в интервале 09:00–10:00 по часовому поясу проекта. `runMaintenance` можно запустить вручную для проверки.
5. Разверните скрипт как веб-приложение с запуском от имени владельца. Для публичной формы нужен доступ «Все» без входа в Google. Для первого теста задайте `TEST_RECIPIENT_EMAIL` перед развёртыванием. Откройте URL из раздела «Управление развёртываниями» и скопируйте адрес с окончанием `/exec` для подключения к сайту.
6. Вставьте URL веб-приложения с окончанием `/exec` в `data-endpoint` файла `templates/price-dialog.html` и запустите `python3 scripts/build.py`. Для проверки с тестовой страницы укажите её origin в `SITE_ORIGIN`. Проверьте настоящий запрос с разрешённого тестового адреса, получение вложения, запись в таблице и обновление статуса после ответа. Для проверки дожима используйте отдельную тестовую таблицу, тестовый адрес и сдвиньте дату статуса на восемь дней назад.

Листы «Заявки» и «Отправки» создаются автоматически. Статусы обновляются по цепочке письма или по адресу клиента, если письмо пришло без заголовков цепочки. Новые ответы ищутся перед дожимом. Google Apps Script хранит настройки в свойствах проекта и читает их заново при запуске.

Доступ к публичному URL позволяет вызвать отправку напрямую. `SITE_ORIGIN` задаёт получателя результата в браузере, а сервер ограничивает первую отправку двумя письмами на адрес и 60 письмами за час. Перед публичным запуском добавьте защиту от ботов с серверной проверкой. На отправку также действуют квоты Google.
